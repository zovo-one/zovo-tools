Manifest V2 to V3 converter for Chrome extensions

By Michael Lip. Updated 2026-11-17.

Paste a Manifest V2 manifest.json and get a Manifest V3 manifest with a change log. Each line of the log links to the developer.chrome.com page with the rule behind the change. The conversion runs entirely in your browser. Your manifest is not uploaded.

      What the converter does
      

        

      • Changes manifest_version from 2 to 3, as the migration guide requires.
        • 

      • Moves host patterns out of permissions and optional_permissions into host_permissions and optional_host_permissions, because host permissions are a separate field in Manifest V3.
        • 

      • Replaces browser_action and page_action with action, as the API migration page requires. When both have the same key, the converter keeps the browser_action value and names the dropped key in the change log.
        • 

      • Turns background.scripts into background.service_worker, because the service worker field takes a string, not an array, and removes background.persistent, as the service worker migration page requires.
        • 

      • Converts each web_accessible_resources string to an object with resources and matches, because each element must include a resources element and either a matches or extension_ids element.
        • 

      • Converts a string content_security_policy to an object with extension_pages, because in Manifest V3 it is a dictionary that supports two properties, extension_pages and sandbox.
        • 

      • Renames _execute_browser_action and _execute_page_action in commands to _execute_action, as the commands reference defines these reserved names. A manifest can hold one _execute_action key, so when both old names are present the converter keeps the _execute_browser_action entry and logs the other one.
        • 

      • Replaces a webRequestBlocking permission with declarativeNetRequest, as the blocking web requests migration page requires. An optional webRequestBlocking becomes a declarativeNetRequest entry in permissions, because declarativeNetRequest is one of the permissions that can not be specified as optional. You must still rewrite the blocking listeners as rules.
        • 

      


      Why you need to convert
      

      Manifest V2 no longer runs in current Chrome. Google states that Chrome 138 is the final version of Chrome to support Manifest V2 extensions (when paired with the ExtensionManifestV2Availability key) and that all remaining Manifest V2 extensions have been removed from the Chrome Web Store. In January 2022 the Chrome Web Store stopped accepting new Manifest V2 extensions with visibility set to "Public" or "Unlisted".
      


      Limits of this tool
      

        

      • This tool converts manifest.json only. It does not change your JavaScript, HTML or CSS. A manifest conversion is not a complete migration.
        • 

      • The converter cannot split more than one background script into a service worker, cannot migrate background.page, cannot rewrite webRequestBlocking blocking rules, and cannot rewrite code calls such as tabs.executeScript. The list "What this converter cannot change" names each of these. The notes about code calls show for every input, because the converter does not read code files.
        • 

      • For each web_accessible_resources string the converter writes "matches": ["*://*/*"]. That pattern is not the same as <all_urls>, because the wildcard scheme matches only http or https. Narrow the matches value to the sites that actually need your resources.
        • 

      • The tool runs in your browser. Your manifest is never sent to a server. The conversion code is part of this page.
        •
